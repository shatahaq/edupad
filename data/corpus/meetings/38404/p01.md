## 1. High-Value Customers

1 / 10

Write a query to find the top 5 customers who have spent the most money across all their completed orders. Return their `full_name` and the total amount spent.

A.

```
SELECT c.full_name, SUM(o.total_amount) AS total_spent
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.full_name
ORDER BY total_spent DESC
LIMIT 5;
```

B.

```
SELECT c.full_name, SUM(o.total_amount) AS total_spent
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
WHERE o.status = 'Completed'
GROUP BY c.customer_id, c.full_name
ORDER BY total_spent DESC
LIMIT 5;
```

C.

```
SELECT c.full_name, MAX(o.total_amount) AS total_spent
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
WHERE o.status = 'Completed'
GROUP BY c.customer_id, c.full_name
ORDER BY total_spent ASC
LIMIT 5;
```

D.

```
SELECT c.full_name, SUM(o.total_amount) AS total_spent
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
WHERE o.status = 'Completed'
ORDER BY total_spent DESC
LIMIT 5;
```

## Foundations of Database Management Systems

A **Database Management System (DBMS)** is system software for creating, managing, and governing structured data. Unlike traditional file systems, a DBMS guarantees data integrity, concurrency control, and multi-user access isolation.

📌 Core Architectural Pillars:

- **Data Abstraction:** Three-schema architecture (Physical, Logical, and View levels).
- **Data Independence:** Logical and physical data independence insulating applications from storage layout shifts.
- **ACID Properties:** Atomicity, Consistency, Isolation, and Durability ensuring transactional reliability.

### Key Components of a DBMS

The core engine consists of the *Query Processor* (parser, optimizer, execution engine) and the *Storage Manager* (buffer manager, transaction manager, recovery manager). Together, they translate declarative commands into high-performance disk and memory operations.

## The Evolution of Database Architectures

Understanding database history illuminates why modern relational and hybrid architectures are designed the way they are.

⏳ Timeline of Database Paradigms:

1. **1960s - Hierarchical & Network Models:** Tightly coupled data navigation (e.g., IBM IMS, CODASYL), prone to rigid schema lock-in.
2. **1970 - Relational Model Inception:** Edgar F. Codd published his landmark paper decoupling logical relations from physical storage.
3. **1980s–1990s - Commercial RDBMS Era:** Standardization of SQL, growth of Oracle, IBM DB2, PostgreSQL, and MySQL.
4. **2000s - The NoSQL Revolution:** Prioritizing horizontal scalability, BASE semantics, and flexible schema for big data (Key-Value, Document, Graph).
5. **Present - NewSQL & Multi-Model DBs:** Combining relational ACID guarantees with horizontal distributed scaling (e.g., CockroachDB, Spanner).

## The Relational Database Model & Integrity Rules

The Relational Model represents data as mathematical relations (tables) composed of attributes (columns) and tuples (rows). It is grounded in first-order predicate logic.

🔑 Fundamental Integrity Constraints:

- **Domain Integrity:** Enforces that all values in a column strictly satisfy defined data types and ranges.
- **Entity Integrity:** Primary keys must be unique and cannot contain `NULL` values.
- **Referential Integrity:** Foreign key references must always point to a valid, existing tuple in the referenced relation or be set explicitly to NULL.

### Relational Normalization Essentials

Normalization reduces redundancy and update anomalies through structured forms: **1NF** (atomic values), **2NF** (no partial dependency), and **3NF/BCNF** (no transitive functional dependencies).

## SQL Query Mastery: DDL, DML, and Advanced Joins

Structured Query Language (SQL) is the standard declarative interface for relational databases. Mastery requires understanding both semantic writing and physical query execution order.

⚡ Logical Query Processing Order:

Unlike procedural languages, SQL executes clauses in this specific sequence:

FROM → ON → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT

### Essential Query Patterns

- **Multi-Table Joins:** Combining `INNER`, `LEFT OUTER`, and `FULL OUTER` joins for relational synthesis.
- **Aggregation & Grouping:** Utilizing `GROUP BY` with aggregate functions and `HAVING` filters.
- **Correlated Subqueries & CTEs:** Writing modular Common Table Expressions (`WITH` clauses) for maintainable, high-performance querying.
